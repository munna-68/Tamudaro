# 2026-09-17

## Tanudaro — added "Today's plan" (daily to-do with progress + time tracking)

User brief: a to-do list for daily goals placed "right after the promo data"
(the pomodoro stats row), tracking what chapter/topic they meant to cover, how
much they got through, and how much time actually went in.

### What shipped

- `src/lib/plan.js` (new) — task model + `planStats`. A task is title + optional
  `target`/`unit` ("4 pages") + `done` counter + banked `focusMs`. Target 1 with
  unit `none` is a plain checkbox, so the basic case is free. Units offered:
  just done / pages / chapters / problems.
- `src/components/PlanCard.jsx` (new) — compact strip mounted directly under
  `StatsRow`: badge `2/5`, weighted progress bar, meta line naming the active
  task. Readout only; all editing is behind it.
- `src/components/PlanSheet.jsx` (new) — pull-up sheet (same drag pattern as
  SummarySheet). Add bar pinned at the *top* so the keyboard can't cover it;
  each row expands in place to a done-stepper, target-stepper, unit chips,
  reorder and two-tap-confirm delete. `▶` marks the task the stopwatch feeds.
- `useTodayLog` gained `addTask/updateTask/nudgeTask/toggleTask/removeTask/
  setActiveTask/moveTask/clearDoneTasks/bankTaskFocus`. All plan writes funnel
  through one `updatePlan(mutate)` helper that always targets `dayKey()`.
- `handleLapComplete` in `App.jsx` now also calls `bankTaskFocus(LAP_MS)`, so a
  banked lap is credited to the active task at full lap length — matching the
  app's existing "laps are banked at their full length, not wall clock" rule.
- Summary sheet gained a "What you planned" section (range totals, per-task rows
  with day stamps, focus time) and a blue plan pill on the day rows.
- `ranges.js` rollup now carries `tasksTotal/tasksDone/planFocusMs/planTasks`.
  `activeDays` was deliberately left counting *lap* days only, since the
  sentence it feeds is about laps.

### Decisions worth remembering

- **Completion is weighted by target, not by task count.** Five chapters and one
  page aren't equal work, so `progress = Σdone / Σtarget`.
- **Plans are per-day and reset at local midnight**, same as focus sessions and
  breaks. Yesterday's plan stays on disk for the summary.
- **`doneAt` is stamped on first completion and cleared if it drops back below
  target** — a stale `doneAt` on an unfinished task is worse than none.
- Storage stayed `version: 1`: `normalizePlan` makes the field purely additive,
  so days written before the feature just read as an empty plan.

### Verification

`/tmp/qa-plan.mjs` — headless Chrome over CDP, Vite run in-process. **57/57
checks passed, zero console errors.** Covered: empty→add→progress→complete→
clear-done flows, `localStorage` persistence, summary section, layout fit at
320×568 / 360×640 / 375×667 / 390×844 / 430×932, keyboard-up geometry, and the
one that mattered most — seeding a stopwatch 100 ms past a lap boundary and
confirming under StrictMode that exactly **one** session banks and the active
task's `focusMs` lands on exactly 1 500 000 ms (not double).

Two things worth keeping in mind for next time: the dev server is a different
origin with its own `localStorage` (state has to be re-seeded per origin), and
four of the first-run failures were my own assertions tripping over
`text-transform: uppercase` in `innerText`. Both now written into the
`sandboxed-web-app-build-qa` skill.
