# 2026-09-12 — Tanudaro: count-up focus timer

## What was built

Scaffolded **Tanudaro** from scratch at `/Users/munna8/workbuddy-ai/Tamudaro`
(note: workspace folder is `Tamudaro`, the app is named `Tanudaro` per the brief).

React 18 + Vite 5, vanilla CSS, `framer-motion` for animation,
`canvas-confetti` for celebrations. No backend — `localStorage` only.

### Key files

- `src/App.jsx` — shell: mode tabs, panels, celebration orchestration, summary sheet
- `src/hooks/useFocusTimer.js` — continuous stopwatch + 25-min lap detection
- `src/hooks/useBreakTimer.js` — countdown break with early-end
- `src/hooks/useTodayLog.js` — day-keyed log, local-midnight rollover
- `src/components/TimerRing.jsx` — SVG ring, lap-wrap handling, finish animation
- `src/components/Mascot.jsx` — the face inside the ring (5 moods)
- `src/lib/time.js` — `LAP_MS`, `dayKey()`, formatters
- `src/styles.css` — cartoon palette, chunky outlines, all responsive rules

### Product decisions worth remembering

- **Day boundary: local midnight.** `dayKey()` derives from
  `getFullYear/getMonth/getDate`, never UTC. Rollover is driven by a 20s
  heartbeat, an exact `setTimeout` to the next midnight, and a
  `visibilitychange`/`focus` check.
- **Ring direction differs by mode.** Focus fills up (0:00 → 25:00); break
  drains down (full → empty), because a countdown reads as "time remaining".
- **The stopwatch never stops at a lap boundary** — it's a continuous lap
  counter. Lap completion banks a session and resets the ring only.
- **Breaks auto-pause the focus stopwatch** and resume it when the break ends,
  so break time is never counted as focus time.
- **Breaks can be ended early** and are still logged, flagged `endedEarly`,
  recording both `plannedSec` and `actualSec`.
- Focus ring is calibrated to a 25-minute lap (`LAP_MINUTES = 25`).

## Environment gotchas hit (now captured as a skill)

Created `~/.workbuddy-ai/skills/sandboxed-web-app-build-qa/`:

1. `npm install` fails with `CODEBUDDY_BROKER_DENY` (brokered `fs` shim via
   `NODE_OPTIONS`). Fix: `NODE_OPTIONS= <node> <npm>/bin/npm-cli.js install`
   with sandbox escalation; clean-reinstall if the tree is partial.
2. A `nohup` dev server is reaped between Bash calls — use
   `run_in_background: true`. Port 5173 was held by another local project.
3. Screenshot QA with zero deps: drive the installed Chrome over CDP using
   Node 22's global `WebSocket`. Don't wait on `Page.loadEventFired`
   (`about:blank` emits a late one) — poll `location.href` instead.
4. **Multiple `Edit` calls to the same file in one message clobber each other**
   while each reporting success. One edit per file per message.
5. Mobile fit must be *measured*, not eyeballed. Fixes applied:
   `height: 100dvh; overflow: hidden` on the shell (not `min-height`),
   `flex-shrink: 0` on form rows, a pinned action bar with only the fields
   scrolling, and a single-row duration grid below 700px height.

## Iteration 2 — custom break duration + personalised reasons

Requested changes:

- Break quick-reasons are now **Namaz / Gosol / Kauah** (the three this user
  actually takes), replacing the generic set. `QUICK_REASONS` in `BreakForm.jsx`
  is now an array of `{emoji, label}`; tapping one sets the reason verbatim.
- The custom duration is no longer a cramped input nested inside a button
  (invalid HTML, and the reason it "didn't do anything"). Tapping the pencil
  tile now morphs it into a centred card via a framer-motion shared `layoutId`,
  where you set the value with −/+ steppers, a direct numeric input, or quick
  chips (5/15/30/45), then confirm with a big green ✓ that flies it back into
  the grid slot. The tile then reads e.g. "40 MIN".

Bugs found and fixed while in there:

- `useBreakTimer.endEarly` ran its side effects (`removeKey`, and firing
  `onComplete` from inside a `setTimeout`) **inside the `setRun` updater**.
  StrictMode double-invokes updaters in dev, so a single early-ended break was
  logged **twice** and fired two celebrations. Side effects now happen outside
  the updater, guarded by `settledRef`.
- Same class of bug in `useFocusTimer`: the lap-banking effect could double-fire
  on StrictMode's double-mount (e.g. a lap crossed while the tab was closed),
  banking a phantom session. Now guarded by `firedLapRef`, which `reset()` and
  `rolloverDay()` keep in sync.
- `rolloverDay` also mutated state inside its updater; rewritten to compute
  outside via a `runRef`.

Verified in headless Chrome: the editor centres exactly (dx 0, dy 0) with the
input autofocused; steppers, quick chips and typing all update the value; ✓
returns the chip showing the right number; the break starts with `plannedSec`
matching; **exactly one** break row per early end AND per natural completion.
Form and editor both fit 360x640 with no scrolling. No console errors.
