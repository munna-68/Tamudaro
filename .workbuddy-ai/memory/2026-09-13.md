# 2026-09-13 — Tanudaro: multi-day stats + keyboard/focus fixes

## Iteration 3 — stats ranges, soft-keyboard overlay, focus lifecycle

Three reported issues, all addressed:

### 1. Stats only covered a single day → added range windows

The summary sheet (📋) was hard-coded to "Today". It now opens on a range and
lets you widen it:

| key | chip | window |
| --- | --- | --- |
| `2d` | "2 days" | today + yesterday — **the default** |
| `7d` | "Week" | rolling 7 days, today included |
| `month` | "Month" | current calendar month, 1st → today |

New `src/lib/ranges.js` is the single source of truth: `RANGE_OPTIONS`,
`rangeDayKeys()`, `summarizeRange()`, `dayLabel()`, `rangeSpanLabel()`.
The log is already day-keyed, so a range is just an ordered list of `dayKey`s —
no data-model change was needed.

- `useTodayLog` now exposes `range`, `setRange`, `rangeStats`, `clearDays`.
  The chosen range persists in `log.settings.range` (normalised in `storage.js`).
- `rangeStats` is `useMemo`'d on `[log.days, range, today]` — `today` is in the
  deps purely so the window slides at local midnight.
- Sheet gained: range picker, a **day-by-day breakdown**, per-break day badges
  (only when the range spans >1 day), and a range-scoped clear.
- Day-list rule: windows ≤7 days list **every** day (a blank yesterday is
  informative, rendered dashed/dimmed); a month lists **only days with
  activity** (31 blank rows would be noise).
- Clear now wipes the **selected range**, so it needs a guard: two-tap confirm
  that also self-cancels after 4s, and resets on range/sheet change.
- Totals keep the existing "banked laps" model — `sum(lapMs)`, not wall-clock.

### 2. Soft keyboard hid the custom-duration editor

Root cause: `position: fixed` resolves against the **layout viewport**, which on
iOS does not shrink when the keyboard opens, so `inset: 0` + `place-items:center`
centred the card behind the keys. Android shrinks the layout viewport, so it only
reproduced on iOS.

- New `src/hooks/useVisualViewport.js` publishes `--vvh` / `--vvt` / `--kb-h`
  and `data-kb="1"` on `<html>` **only while a keyboard is up**, so
  `var(--x, <old value>)` degrades to the previous behaviour everywhere else.
- `.editor-layer` → `top: var(--vvt)` + `height: var(--vvh)`; `.editor` →
  `max-height: 100%` + internal scroll.
- `.sheet` → `bottom: var(--kb-h, 0px)`.
- `.app` → `height: var(--vvh, 100dvh)` so the shell shrinks to the visible slice.
- While `data-kb='1'`: hide `.topbar`, `.stats`, `.form-head` and compact the
  tabs. Without this the shell shrank but the field you're typing in stayed
  below the fold (measured: at a realistic 508px visible height the scroll area
  went 471px → 232px, and the textarea at y=293 was clipped).

### 3. "Focus breaks" in the editor

- Dropped `autoFocus` (fires before the shared-layout flight settles; iOS drops
  it). Focus now happens in `useLayoutEffect` with
  `focus({ preventScroll: true })` + one 120ms retry guarded by
  `document.activeElement !== input`.
- `closeEditor()` now **blurs before closing** and restores focus to the custom
  tile after the exit animation. Letting the input unmount while it owned focus
  left nothing focused, so the next tap was swallowed.
- Added `Enter` → confirm, `enterKeyHint="done"`, `autoComplete/Correct off`.

## Environment gotchas (added to the `sandboxed-web-app-build-qa` skill)

- **Chrome + sandbox proxy:** requesting `http://[::1]:5173/` from Chrome got
  served a *third-party site* with `status=200` while `curl` got the real app.
  Fix: bind Vite with `--host 127.0.0.1` (it was binding `[::1]` despite the
  config) and launch Chrome with `--no-proxy-server` + scrubbed proxy env.
  Always assert `document.title` before screenshotting.
- **`puppeteer-core` silently dropped a nested object** passed to `evaluate`
  (`days: {...}` arrived as `{}`), so the seeded log rendered as all zeros.
  Pass `JSON.stringify(...)` and `JSON.parse` in-page; seed via
  `evaluateOnNewDocument` so it lands before app code writes its own defaults.
